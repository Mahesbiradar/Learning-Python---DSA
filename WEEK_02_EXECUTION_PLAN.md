Phase: Month 1 - Arrays + Hashing + Strings  
Dates: starts after Week 1 review on 2026-05-14

## Week 2 Goals

- Get LeetCode proof back on track.
- Convert near-mastered local problems into verified problems.
- Repair medium hashing dependence before increasing volume.
- Keep daily work sustainable: 3 new problems max, 2 revision problems max.
- Avoid burnout by blocking optional work until required proof is complete.

| Target | Minimum |

## Daily Structure

1. Fundamentals warm-up: 20-30 minutes.
2. Revision first: 1-2 old problems.
3. New problems: 2-3 maximum.
4. LeetCode submission: at least 1 accepted before optional work.
5. Reflection: fill independent/hint/solution/unsolved status the same day.

## Fundamentals Alignment

Daily drill:
- Write `freq[x] = freq.get(x, 0) + 1`.
- Write one dry-run table for pointer or prefix state.
- Write one complexity line using real variables: `n`, `m` unique values, `k` max word length.
- Test one empty/no-answer case before submitting.

## Mock-Test Strategy

Run the mock only after at least two study days have recorded accepted LeetCode submissions.

Mock format:
- 1 easy proof problem.
- 2 medium hashing/prefix problems.
- 1 old failed problem.
- 60-75 minutes.
- No hints.

Review format:
- Record failed cases.
- Identify pattern trigger missed.
- Fix complexity notes.
- Add unresolved problems to failed queue.

## Pacing Rules

Continue forward when:
- Two consecutive days have 70%+ clean independent work.
- At least one accepted LeetCode submission is recorded per study day.
- Group Anagrams and Top K sorting can be re-solved without solution help.

Repeat consolidation when:
- Any medium hashing problem needs full solution viewing.
- Product Except Self optimized form is still unclear.
- Pivot Index still misses no-answer return.

Slow down when:
- Daily reflection is blank.
- LeetCode proof is skipped.
- Optional work starts before required revision.
- Same complexity mistake appears twice.
